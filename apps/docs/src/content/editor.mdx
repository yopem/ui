## Foundation scope

Editor provides core rich text editing with Lexical, React, and StyleX. Use the
toolbar or keyboard shortcuts to format text. Use lists and history controls to
organize and revise content.

This editor does not provide full Plate open-source parity. Media,
collaboration, and the complete Plate plugin set remain outside this scope. The
preset includes table insertion and table actions. Compose additional table
controls for dimensions, presentation, and column resizing.

## Installation

[Initialize your project](/docs/installation) before you add Editor. Run the
command from your application directory. Use the switcher to select Bun, npm,
pnpm, or Yarn 2 and later.

```sh
bunx --bun @yopem-ui/cli add editor
```

The CLI copies Editor source and installs its dependencies. Keep your
application's StyleX build integration and root styles enabled. See the
[component reference](/components/editor) for source files and dependencies.

## Usage

Import Editor from the copied source.

```tsx
"use client"

import { Editor } from "@/components/editor"

export function NotesEditor() {
  return <Editor ariaLabel="Notes" placeholder="Write your notes…" />
}
```

`onChange` receives the Lexical `EditorState` and `LexicalEditor` instance. Call
`state.toJSON()` to obtain the document for storage. The example below displays
this output without saving it to a server.

## Compose editor parts

Use `Editor` for the preset toolbar and editable surface. Use public parts to
choose controls, order them, or add application controls. Each `EditorRoot`
keeps its own document and history.

`EditorRoot` accepts `initialState`, `onChange`, `editable`, and `ariaLabel`.
`EditorContent` shares the root name and read-only state. It accepts native
editable attributes, a ref, `className`, `xstyle`, and an optional placeholder.
`EditorToolbar` provides keyboard navigation and accepts children. Its default
name uses the root name followed by `formatting`.

<EditorCompositionExamples />

```tsx
"use client"

import {
  EditorRoot,
  EditorContent,
  EditorToolbar,
  EditorFormatButton,
  EditorHistoryButton,
  EditorBlockButton,
} from "@/components/editor"

export function ComposedNotes() {
  return (
    <EditorRoot ariaLabel="Composed editor">
      <EditorToolbar aria-label="Custom formatting">
        <EditorFormatButton format="bold" />
        <EditorFormatButton format="italic" />
        <EditorHistoryButton action="undo" />
        <EditorHistoryButton action="redo" />
        <EditorBlockButton block="h2" />
      </EditorToolbar>
      <EditorContent placeholder="Write your notes…" />
    </EditorRoot>
  )
}
```

Choose `EditorFormatButton` for Lexical text formats. Use `EditorBlockButton`
for paragraph, h1 through h6, quote, or code blocks. Use `EditorHistoryButton`
for undo or redo. Use `EditorListButton` with bullet, number, or check.
`EditorIndentButton` accepts indent or outdent. `EditorLinkControl` validates
link URLs. `EditorTableButton` inserts a three-row, three-column table.

Controls accept native control props, refs, `className`, and `xstyle`. A
consumer `onClick` can prevent the command with `event.preventDefault()`. Keep
controls and the editable surface inside their `EditorRoot`. Use `useEditor` for
the Lexical instance. Use `useEditorState` for current text formats, history
availability, root name, and read-only state. These hooks require `EditorRoot`.
This composition API does not provide Plate plugin or document compatibility.

## Text and block styles

Select text before you open a style control. Keep all controls inside their
`EditorRoot`. Saved selections become invalid after document changes.

<EditorStyleExample />

```tsx
"use client"

import {
  EditorRoot,
  EditorContent,
  EditorToolbar,
  EditorAlignmentButton,
  EditorFontColorControl,
  EditorBackgroundColorControl,
  EditorFontFamilyControl,
  EditorFontSizeControl,
  EditorFontWeightControl,
  EditorLineHeightControl,
  EditorFirstLineIndentControl,
  EditorClearFormattingButton,
  EditorBlockPresentationExtension,
} from "@/components/editor"

const extensions = [EditorBlockPresentationExtension]

export function StyledNotes() {
  return (
    <EditorRoot ariaLabel="Styled notes" extensions={extensions}>
      <EditorToolbar aria-label="Text styles">
        <EditorAlignmentButton alignment="start" />
        <EditorAlignmentButton alignment="center" />
        <EditorAlignmentButton alignment="end" />
        <EditorAlignmentButton alignment="justify" />
        <EditorFontColorControl />
        <EditorBackgroundColorControl />
        <EditorFontFamilyControl />
        <EditorFontSizeControl />
        <EditorFontWeightControl />
        <EditorLineHeightControl />
        <EditorFirstLineIndentControl />
        <EditorClearFormattingButton />
      </EditorToolbar>
      <EditorContent />
    </EditorRoot>
  )
}
```

Keep the extension array outside the component. Register
`EditorBlockPresentationExtension` once at mount time, including read-only
editors. This Lexical extension does not require React.

Use `EditorIndentButton` for block indentation. Use
`EditorFirstLineIndentControl` for first-line indentation. Line height accepts
unitless values from 1 through 4. First-line indentation accepts nonnegative
values through 160px or 10em/rem.

Font controls apply inline text styles. Colors accept theme palette values or
3-, 6-, and 8-digit hexadecimal values. Families accept Inter, Arial, Georgia,
IBM Plex Mono, serif, sans-serif, and monospace. Font sizes accept positive
values through 160px or 10em/rem. Font weights accept 100 through 900 in steps
of 100. Invalid values do not change the document.

Clear formatting removes selected text marks, inline styles, alignment, and
managed block styles. It keeps content, links, node types, list nesting, table
structure, direction, and unrelated NodeState. At a caret, it clears typing
styles without changing existing text. Undo restores formatting changes.

### Block presentation storage

Import pure helpers from `@/components/editor/block-presentation` for server
codecs. `parseEditorBlockPresentation` accepts the payload at
`node.$.editorBlockPresentation`, not the complete serialized node.

```ts
import { parseEditorBlockPresentation } from "@/components/editor/block-presentation"

const presentation = parseEditorBlockPresentation({
  lineHeight: "2",
  textIndent: "24px",
})
```

The result always contains `lineHeight` and `textIndent` strings. Invalid fields
become empty strings independently. Unknown fields are removed. Read live state
with `$getEditorBlockPresentation` inside a Lexical read or update. Write
validated state with `$setState` and `editorBlockPresentationState`. Keep other
NodeState entries unchanged.

The extension preserves these values in Lexical JSON and HTML. Its HTML hooks
keep native converter priority, child callbacks, and export slots. For custom
block classes, use `createEditorBlockPresentationHTMLConfig` with every
supported class. Combine its maps with host HTML overrides. These hooks do not
sanitize HTML. Keep host HTML sanitization in place.

## Add Lexical extensions

Pass Lexical extensions through `EditorRoot` or the `Editor` preset. Define the
extension list outside the component. Extensions can register nodes, commands,
and cleanup functions through the Lexical lifecycle.

<EditorExtensionExamples />

The live example registers a custom note command.

Use **Replace document** to load a new editor state. With **Link** open, press
`Alt+Shift+R` to apply a host update. Saved link selections become invalid after
content changes.

This example enables the first-party autofocus extension:

```tsx
import { AutoFocusExtension } from "@lexical/extension"
import { Editor, type EditorProps } from "@/components/editor"

const extensions = [AutoFocusExtension]

export function AppEditor(props: EditorProps) {
  return <Editor {...props} extensions={extensions} />
}
```

Treat extensions as initial configuration. Remount the editor when you change
the extension list. Existing Plate plugins cannot run inside this Lexical
lifecycle.

Use [editor authentication](/docs/editor-auth) to connect existing OpenAuth or
Better Auth services to your backend. The editor does not authenticate users or
save documents automatically.

## Tables

Use `EditorTableMenu` to insert or delete rows and columns. It also changes
headers, merges selected cells, splits merged cells, and deletes tables.
`EditorTableDimensions` inserts a table with selected dimensions.

Register `EditorTablePresentationExtension` to validate table updates and retain
cell presentation. Add `EditorTableCellPresentation` for backgrounds and
borders. Use `EditorTableBorderControls` separately for individual and rectangle
edges. Add `EditorTableResizeControls` for column widths and row minimum
heights.

Tall tables scroll inside a keyboard-focusable area.

Row height is a stored minimum. Content can make a row taller. Pointer resizing
starts from visible row height. Keyboard resizing changes the stored minimum.
Use Home to clear the minimum. Up and Down change it by 10 pixels. Merged cell
edges are indivisible. Changes apply to each complete shared edge. Border
controls mirror adjacent edges. This prevents hidden borders from hiding a new
solid edge. Legacy solid and hidden border values remain valid. Per-edge values
use top, bottom, start, and end.

Merge uses a solid edge when any perimeter segment is solid. Otherwise, merge
keeps hidden edges only when all perimeter segments are hidden. Split keeps
perimeter edges and resets new inside edges.

Saved border metadata remains unchanged during display. Solid edges take display
precedence over conflicting hidden edges. HTML uses `data-editor-border` for
border metadata. Import rejects unsupported border CSS instead of removing it.

HTML stores native row heights in `data-editor-row-height`. Keep this attribute
when processing exported tables. CSS alone can change imported values.
`parseTableRowHeightHTML` reads this attribute. It returns `undefined` for
missing or invalid metadata.

<EditorTableExamples />

```tsx
"use client"

import {
  EditorRoot,
  EditorContent,
  EditorToolbar,
  EditorTableMenu,
  EditorTableDimensions,
  EditorTableCellPresentation,
  EditorTableResizeControls,
  EditorTablePresentationExtension,
} from "@/components/editor"

const extensions = [EditorTablePresentationExtension]

export function TableNotes() {
  return (
    <EditorRoot ariaLabel="Table notes" extensions={extensions}>
      <EditorToolbar>
        <EditorTableMenu />
      </EditorToolbar>
      <EditorTableDimensions />
      <EditorTableCellPresentation />
      <EditorContent />
      <EditorTableResizeControls />
    </EditorRoot>
  )
}
```

Drag a column separator to change its width. Focus a separator for keyboard
control. Left and Right change width. Home and End select the width limits.
Escape cancels a drag. Right-to-left layout reverses horizontal movement.
Read-only mode disables editing and cancels active resizing.

Table limits are 50 rows, 50 columns, and 2500 covered cells across the
document. Merged cells count toward this limit. Column widths range from 48 to
640 pixels. Invalid updates preserve the previous document instead of removing
table data.

Call `parseTablePresentationJSON` before you load external table JSON. Call
`validateTablePresentationHTML` before you convert external table HTML. These
functions check table limits and geometry. They do not replace application
validation or HTML sanitization. Use the configured editor nodes for conversion.

Register `TABLE_PRESENTATION_ERROR_COMMAND` to report rejected clipboard input.
Store its cleanup function through the Lexical extension lifecycle. The example
reports errors without changing existing content.

The example supports two host shortcuts. `Alt+Shift+R` changes read-only mode.
`Alt+Shift+N` replaces the document. Saved table selections become invalid after
content changes. Table JSON and HTML reload controls exercise serialization.

## Initial state and read-only content

Pass Lexical JSON or its JSON string to `initialState` when the editor mounts.
The prop sets initial content; it is not a controlled value. Set
`editable={false}` to display read-only content. Give each editor a distinct
`ariaLabel`. The default accessible name is `Rich text editor`.

```tsx
import { Editor } from "@/components/editor"
import type { EditorProps } from "@/components/editor"

export function SavedNotes({
  initialState,
}: Pick<EditorProps, "initialState">) {
  return (
    <Editor
      ariaLabel="Saved notes"
      editable={false}
      initialState={initialState}
    />
  )
}
```

## Storage and migration

Lexical JSON is not compatible with Slate or Plate JSON. Do not pass a Slate
document to `initialState`. Convert existing content to supported Lexical nodes
before you load it. Keep a backup of the original document during migration.

Validate documents at your application's storage boundaries. This example does
not provide persistence, migration, or server validation. Only load node types
that your editor registers.

## API

| Prop           | Type                                                  | Default            |
| -------------- | ----------------------------------------------------- | ------------------ |
| `initialState` | `SerializedEditorState` or `string`                   | Empty document     |
| `onChange`     | `(state: EditorState, editor: LexicalEditor) => void` | Not set            |
| `editable`     | `boolean`                                             | `true`             |
| `ariaLabel`    | `string`                                              | `Rich text editor` |
| `placeholder`  | `string`                                              | Component default  |

`Editor`, `EditorProps`, and the document model use the Lexical foundation. See
the [component reference](/components/editor) for the generated API.

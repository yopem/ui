## Foundation scope

Editor provides core rich text editing with Lexical, React, and StyleX. Use the
toolbar or keyboard shortcuts to format text. Use lists and history controls to
organize and revise content.

This editor does not provide full Plate open-source parity. Media,
collaboration, and the complete Plate plugin set remain outside this scope. The
preset includes table insertion and table actions. Compose additional table
controls for dimensions, presentation, and column resizing.

## Installation

[Initialize your project](/docs/installation) before you add Editor. Run the
command from your application directory. Use the switcher to select Bun, npm,
pnpm, or Yarn 2 and later.

```sh
bunx --bun @yopem-ui/cli add editor
```

The CLI copies Editor source and installs its dependencies. Keep your
application's StyleX build integration and root styles enabled. See the
[component reference](/components/editor) for source files and dependencies.

## Usage

Import Editor from the copied source.

```tsx
"use client"

import { Editor } from "@/components/editor"

export function NotesEditor() {
  return <Editor ariaLabel="Notes" placeholder="Write your notes…" />
}
```

`onChange` receives the Lexical `EditorState` and `LexicalEditor` instance. Call
`state.toJSON()` to obtain the document for storage. The example below displays
this output without saving it to a server.

## Compose editor parts

Use `Editor` for the preset toolbar and editable surface. Use public parts to
choose controls, order them, or add application controls. Each `EditorRoot`
keeps its own document and history.

`EditorRoot` accepts `initialState`, `onChange`, `editable`, and `ariaLabel`.
`EditorContent` shares the root name and read-only state. It accepts native
editable attributes, a ref, `className`, `xstyle`, and an optional placeholder.
`EditorToolbar` provides keyboard navigation and accepts children. Its default
name uses the root name followed by `formatting`.

<EditorCompositionExamples />

```tsx
"use client"

import {
  EditorRoot,
  EditorContent,
  EditorToolbar,
  EditorFormatButton,
  EditorHistoryButton,
  EditorBlockButton,
} from "@/components/editor"

export function ComposedNotes() {
  return (
    <EditorRoot ariaLabel="Composed editor">
      <EditorToolbar aria-label="Custom formatting">
        <EditorFormatButton format="bold" />
        <EditorFormatButton format="italic" />
        <EditorHistoryButton action="undo" />
        <EditorHistoryButton action="redo" />
        <EditorBlockButton block="h2" />
      </EditorToolbar>
      <EditorContent placeholder="Write your notes…" />
    </EditorRoot>
  )
}
```

Choose `EditorFormatButton` for Lexical text formats. Use `EditorBlockButton`
for paragraph, h1 through h6, quote, or code blocks. Use `EditorHistoryButton`
for undo or redo. Use `EditorListButton` with bullet, number, or check.
`EditorIndentButton` accepts indent or outdent. `EditorLinkControl` validates
link URLs. Select an existing link to edit its URL, text, and new-tab setting.
Unchanged link text keeps its native children and formatting. Explicit edits
turn automatic links into manual links. `EditorTableButton` inserts a three-row,
three-column table.

Core editing links plain HTTP and HTTPS URLs, `www` addresses, and email
addresses. Code blocks and inline code do not expose automatic navigation.
Automatic links use native `AutoLinkNode` state, including explicit unlink
state. Register `AutoLinkNode` in custom readers that load core editor JSON.

Controls accept native control props, refs, `className`, and `xstyle`. A
consumer `onClick` can prevent the command with `event.preventDefault()`. Keep
controls and the editable surface inside their `EditorRoot`. Use `useEditor` for
the Lexical instance. Use `useEditorState` for current text formats, history
availability, root name, and read-only state. These hooks require `EditorRoot`.
This composition API does not provide Plate plugin or document compatibility.

Keep the extension array outside the component. Register
`EditorBlockPresentationExtension` once at mount time, including read-only
editors. This Lexical extension does not require React.

Use `EditorIndentButton` for block indentation. Use
`EditorFirstLineIndentControl` for first-line indentation. Line height accepts
unitless values from 1 through 4. First-line indentation accepts nonnegative
values through 160px or 10em/rem.

Font controls apply inline text styles. Colors accept theme palette values or
3-, 6-, and 8-digit hexadecimal values. Families accept Inter, Arial, Georgia,
IBM Plex Mono, serif, sans-serif, and monospace. Font sizes accept positive
values through 160px or 10em/rem. Font weights accept 100 through 900 in steps
of 100. Invalid values do not change the document.

Clear formatting removes selected text marks, inline styles, alignment, and
managed block styles. It keeps content, links, node types, list nesting, table
structure, direction, and unrelated NodeState. At a caret, it clears typing
styles without changing existing text. Undo restores formatting changes.

### Block presentation storage

Import pure helpers from `@/components/editor/block-presentation` for server
codecs. `parseEditorBlockPresentation` accepts the payload at
`node.$.editorBlockPresentation`, not the complete serialized node.

```ts
import { parseEditorBlockPresentation } from "@/components/editor/block-presentation"

const presentation = parseEditorBlockPresentation({
  lineHeight: "2",
  textIndent: "24px",
})
```

The result always contains `lineHeight` and `textIndent` strings. Invalid fields
become empty strings independently. Unknown fields are removed. Read live state
with `$getEditorBlockPresentation` inside a Lexical read or update. Write
validated state with `$setState` and `editorBlockPresentationState`. Keep other
NodeState entries unchanged.

The extension preserves these values in Lexical JSON and HTML. Its HTML hooks
keep native converter priority, child callbacks, and export slots. For custom
block classes, use `createEditorBlockPresentationHTMLConfig` with every
supported class. Combine its maps with host HTML overrides. These hooks do not
sanitize HTML. Keep host HTML sanitization in place.

## Tables

Use `EditorTableMenu` to insert or delete rows and columns. It also changes
headers, merges selected cells, splits merged cells, and deletes tables.
`EditorTableDimensions` inserts a table with selected dimensions.

Register `EditorTablePresentationExtension` to validate table updates and retain
cell presentation. Add `EditorTableCellPresentation` for backgrounds and
borders. Use `EditorTableBorderControls` separately for individual and rectangle
edges. Add `EditorTableResizeControls` for column widths and row minimum
heights.

Tall tables scroll inside a keyboard-focusable area.

Row height is a stored minimum. Content can make a row taller. Pointer resizing
starts from visible row height. Keyboard resizing changes the stored minimum.
Use Home to clear the minimum. Up and Down change it by 10 pixels. Merged cell
edges are indivisible. Changes apply to each complete shared edge. Border
controls mirror adjacent edges. This prevents hidden borders from hiding a new
solid edge. Legacy solid and hidden border values remain valid. Per-edge values
use top, bottom, start, and end.

Merge uses a solid edge when any perimeter segment is solid. Otherwise, merge
keeps hidden edges only when all perimeter segments are hidden. Split keeps
perimeter edges and resets new inside edges.

Saved border metadata remains unchanged during display. Solid edges take display
precedence over conflicting hidden edges. HTML uses `data-editor-border` for
border metadata. Import rejects unsupported border CSS instead of removing it.

HTML stores native row heights in `data-editor-row-height`. Keep this attribute
when processing exported tables. CSS alone can change imported values.
`parseTableRowHeightHTML` reads this attribute. It returns `undefined` for
missing or invalid metadata.

```tsx

  return (

      <EditorToolbar>

```

Drag a column separator to change its width. Focus a separator for keyboard
control. Left and Right change width. Home and End select the width limits.
Escape cancels a drag. Right-to-left layout reverses horizontal movement.
Read-only mode disables editing and cancels active resizing.

Table limits are 50 rows, 50 columns, and 2500 covered cells across the
document. Merged cells count toward this limit. Column widths range from 48 to
640 pixels. Invalid updates preserve the previous document instead of removing
table data.

Call `parseTablePresentationJSON` before you load external table JSON. Call
`validateTablePresentationHTML` before you convert external table HTML. These
functions check table limits and geometry. They do not replace application
validation or HTML sanitization. Use the configured editor nodes for conversion.

Register `TABLE_PRESENTATION_ERROR_COMMAND` to report rejected clipboard input.
Store its cleanup function through the Lexical extension lifecycle. The example
reports errors without changing existing content.

The example supports two host shortcuts. `Alt+Shift+R` changes read-only mode.
`Alt+Shift+N` replaces the document. Saved table selections become invalid after
content changes. Table JSON and HTML reload controls exercise serialization.

## Initial state and read-only content

Pass Lexical JSON or its JSON string to `initialState` when the editor mounts.
The prop sets initial content; it is not a controlled value. Set
`editable={false}` to display read-only content. Give each editor a distinct

```tsx
import { Editor } from "@/components/editor"
import type { EditorProps } from "@/components/editor"

export function SavedNotes({
  initialState,
}: Pick<EditorProps, "initialState">) {
  return (
    <Editor
      ariaLabel="Saved notes"
      editable={false}
      initialState={initialState}
    />
```

## Document import and export

Install the optional document item with your selected package manager.

```sh
bunx --bun @yopem-ui/cli add editor-document
```

This item includes editor and editor-blocks. Base editor installs do not include
document codecs. Keep every copied file, including `document/state.ts` and both
pure presentation helpers.

Import portable helpers from `@/components/editor/document`. This entry does not
load React, UI components, or a DOM library. Import `DocumentStatic` separately
from `@/components/editor/document/static` for React server or client rendering.

<EditorDocumentExamples />

Pass the Lexical editor from `useEditor` inside `EditorRoot`. Call the helper
from a host event handler.

```ts
import type { LexicalEditor } from "lexical"
import {
  importDocument,
  exportDocument,
  parseDocument,
  htmlDocument,
} from "@/components/editor/document"

export function replaceNotes(editor: LexicalEditor) {
  importDocument(editor, "# Notes", "markdown")
  const markdown = exportDocument(editor, "markdown")
  const validatedState = parseDocument(markdown, "markdown")
  const standalone = htmlDocument(editor, "Notes")
  return { markdown, validatedState, standalone }
}
```

`parseDocument` validates without changing a live editor. `importDocument`
replaces editable content after validation and adds one undo step. Invalid input
keeps the previous state. JSON uses native Lexical state, not Slate state.

Use `documentNodes` when you create a custom headless editor. Imports reject a
target that cannot keep the parsed fields and children.

HTML import accepts supported document fragments, not arbitrary webpages. Active
HTML, unknown styles, unsafe links, unmarked media, and unsupported nodes
produce errors. Register math and mention nodes before importing their
representations. Markdown supports TeX delimiters with canonical HTML fallback
when required for fidelity. Static and standalone HTML use native MathML.
Mention Markdown uses the validated identity codec. Saved identities do not
grant access. Media JSON and canonical tagged figure HTML retain native
metadata. Markdown uses canonical HTML for media. Register `MediaExtension` for
live rendering or `MediaNode` in headless readers. Both native media and the
portable reader require absolute HTTPS source and track URLs without
credentials. The portable reader rejects nonempty query or fragment components.
It may retain empty trailing `?` or `#` on ordinary media and track URLs,
subject to other checks. Native `MediaNode` JSON and tagged HTML use
`parseMedia`. Ordinary media and track URLs can contain nonempty queries or
fragments there. Provider, tweet, and iframe rules can be stricter. Review
formats remain unsupported. Plain text does not carry those semantics. Handle
`DocumentError.diagnostics` at the host boundary. JSON retains supported
NodeState. HTML and Markdown retain supported element NodeState. Persisted
code-view booleans require JSON; HTML and Markdown report diagnostics. Portable
export rejects paragraph-owned slots to prevent loss of ownership. Use JSON for
these documents. Standalone HTML, downloads, and DOCX export also reject these
slots. Other slot ownership cases still need validation.

Readers also retain validated footnotes, table of contents, columns, dates,
labels, drawings, editable cards, and diagram metadata. Register the matching
native feature nodes before live import. Keep canonical markers, references,
slots, and NodeState. Optional nodes use canonical HTML fallback in Markdown.
Markdown footnote input is supported. Drawings keep scene metadata without SDK
rendering. Editable cards keep their saved node, not transient form values or
nested-editor drafts. Review state still rejects before replacement.

Keep every copied pure model and `document/optional-nodes.ts`. Keep
`@types/hast` and `@types/mdast` as direct consumer dependencies. The optional
codec workflows remain unverified until deferred checks run.

Markdown uses HTML fallback to retain whitespace. Use JSON for native text with
carriage returns or invalid HTML characters. JSON escapes retain these values in
metadata.

Links keep supplied safe relations. Blank-window links add `noopener` and
`noreferrer`. Use `_self` or `_blank` for link targets. Do not use `opener`
relations. Empty link titles and relations use native null defaults.

Tables retain spans, edge borders, row metadata, widths, and supported block
styles. Keep `data-editor-row-height`; native CSS can clamp finite row heights.
Markdown uses safe HTML when plain Markdown cannot retain supported metadata.

Each document has separate limits: 1 MiB UTF-8, depth 64, and 65,536 structural
objects or arrays. Tables also have 50-row, 50-column, and 2,500-slot limits. A
valid 50-by-50 table can still exceed another document limit.

`exportDocument` returns fragments or Markdown source. It keeps CSS variable
references for the host renderer. Use standalone HTML for a theme-independent
file.

`htmlDocument` produces escaped standalone HTML. Mounted editors supply
validated selected color variables and their foreground/background pair.
Unresolved color variables fail when theme context is absent. Headless exports
without variables use black text and a white background. Supply an opaque host
surface for mounted exports. Partially transparent surfaces produce an error.
Color variables with context-relative values, such as `currentColor`, produce an
error. Standalone files name Inter and IBM Plex Mono with local fallbacks; they
do not download fonts.

Use `downloadDocument(editor, "html", ownerDocument)` for HTML files. Use
`"markdown"` for Markdown files. `DocumentStatic` validates its HTML fragment
before rendering. It does not load editing controls or bypass sanitization.

Optional `idPrefix` has 1–64 ASCII characters. Start with an ASCII letter. Use
ASCII letters, digits, underscores, or non-consecutive hyphens after it. Invalid
prefixes throw. Use the same stable prefix for server rendering and hydration.
Use a distinct prefix for each document in one owner document. Reserve generated
IDs against other host markup. Choose distinct, meaningful `aria-label` values
for multiple documents.

A prefix changes rendered IDs and fragment targets to
`<idPrefix>--<canonical-id>`. Update deep links when opting in. Native fragment
activation can change the URL and browser history. Changing a prefix changes its
links. Omitting `idPrefix` preserves canonical IDs and existing deep links, but
does not isolate multiple instances. Static prefixing does not change document
data. Prefixed markup is not portable document HTML.

`streamMarkdown` accepts an async text iterator and an optional abort signal. It
commits once after verified EOF. Cancellation, source failure, read-only
changes, and stale content preserve the current document. Progress is
provisional text, not committed editor state. Cleanup requests cannot stop an
uncooperative producer.

Register `EditorDocumentClipboardExtension` in the stable editor extension
array. Call `registerDocumentPaste` after editor creation. Keep its cleanup in
the host lifecycle. Cleanup restores native clipboard import. The helper
requires the extension and rejects duplicate registration.

Native defaults select JSON before HTML. The boundary validates complete JSON
and HTML fragments before default paste imports. Invalid or foreign JSON can use
a valid HTML fallback. Without that fallback, the boundary blocks default text
and URI imports. Invalid HTML stops import without document changes.

Host command vetoes, MIME handler order, and MIME priorities keep native
behavior. Host MIME handlers that consume data must validate their own output.
Direct imports without `PASTE_TAG` and drop handlers keep native behavior.

## Storage and migration

Lexical JSON is not compatible with Slate or Plate JSON. Do not pass a Slate
document to `initialState`. Convert existing content to supported Lexical nodes
before you load it. Keep a backup of the original document during migration.

Validate documents at your application's storage boundaries. This example does
not provide persistence, migration, or server validation. Only load node types
that your editor registers.

### Document schema

Import server-safe models and validators from
`@/components/editor/blocks-model`. All four nodes use Lexical element fields
and version `1`. `editor-callout` adds `appearance` and `icon` fields.
`appearance` accepts neutral, info, success, warning, or destructive. `icon`
accepts up to 32 UTF-16 units of plain text, including emoji joiners.
`editor-toggle` adds a boolean `open` field. Its children must be
`editor-toggle-summary` followed by `editor-toggle-body`. Summary and body nodes
have no additional fields.

HTML uses `aside[data-editor-callout]` with `data-appearance` and `data-icon`.
Toggle HTML uses `section[data-editor-toggle]` with two children. The first
child is `div[data-editor-toggle-summary]` for the rich title. The second child
is `details[data-editor-toggle-body]` with the native `open` attribute. The
details element contains an empty `summary[data-editor-toggle-control]` and
`div[data-editor-toggle-content]`. The control uses the plain title as its
accessible name, or `Toggle content` for an empty title. Title links stay
outside the disclosure control and remain visible when closed. Import also
accepts the earlier marked details, summary, and body-div structure. The icon
attribute stores metadata. Rendering shows the icon outside the editable child
slot.

Call `validateEditorBlocksJSON` before Lexical JSON parsing. Call
`validateEditorBlocksHTML` before HTML conversion. These validators check block
metadata, structure, depth, and size limits. They do not replace host
sanitization, complete node validation, or document access checks. Reject
unsupported content before replacing the current document. Keep table and
block-presentation validators active when those extensions are installed. Do not
remove unknown nodes or convert them to text.

Browser parity checks remain required for clipboard, cross-block selection,
history, and assistive technology. This feature does not provide Plate document
compatibility or full Plate parity.

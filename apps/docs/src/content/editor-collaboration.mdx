## Scope and status

Use optional collaboration source with an existing authenticated host
application. Choose Durable Objects with D1 or PostgreSQL with a Bun or Node
adapter. This guide describes source contracts only. It does not confirm runtime
or deployment validation.

The client uses native Lexical Yjs bindings, per-client history, and remote
cursors. Its custom `editor-v1` protocol uses binary document frames and bounded
text controls for readiness, delivery, and acknowledgements. It is not a
`y-websocket` service. Keep these protocol text controls; reject arbitrary text.

No account system, ACL system, default endpoint, credentials, or deployment is
included. No AI model is required. Configure any separate AI service explicitly
on the host.

## Supply host authorization

Reuse existing OpenAuth or Better Auth authentication. Set an explicit OpenAuth
audience. Better Auth verification must not refresh sessions. Forward verified
`credentialExpiresAt` in Unix epoch milliseconds. Never derive expiry from
unverified browser data.

Supply external per-document policies for `collab:read`, `collab:write`, and
`document:write`. Only literal `true` permits access. Authentication and stored
document rows do not grant access. Snapshot promotion also requires document
write permission. Keep deletion and offline migration behind separate host
authorization.

Configure one exact serialized HTTPS origin without a trailing slash. Both
ticket and socket requests require the exact `Origin`. Verify `X-CSRF-Token` on
ticket POST requests against the authenticated host session. The ticket request
also requires `X-Editor-Permission` with `read` or `write`.

Use an explicit base path, such as `/collaboration/`. The endpoints are
`/collaboration/{encodedDocumentId}/ticket` and
`/collaboration/{encodedDocumentId}/socket`. Do not add query parameters. Never
put authentication tokens or tickets in URLs or logs. Tickets travel in the
WebSocket subprotocol offer with `editor-v1`. Select only `editor-v1` in the
upgrade response. Do not echo the ticket.

Implement `revalidate` with current authentication, verified expiry, document
generation, and current document policy. Run recipient checks before outbound
delivery, not only when a sender connects. Keep these callbacks abort-aware and
bounded. Recipient checks do not make revocation atomic with database commits or
sends. Use a separate host fence when immediate revocation must be atomic.

## Create a schema-complete initializer

Use `createEditorCollaborationInitializer({ createEditor, validateState })`.
`createEditor(schemaVersion)` must return a headless `LexicalEditorWithDispose`
with the complete supported node schema. Use `buildEditorFromExtensions` with
`HeadlessExtension` and host node extensions. Keep its native `dispose` cleanup.
Use the same node classes, replacements, custom NodeState, and schema version as
the browser document. Install the host headless editor dependencies explicitly.

`validateState(state, schemaVersion)` must validate the complete document before
promotion. An object check or root-envelope check is insufficient. Reject
unsupported nodes, versions, metadata, and schema versions. The initializer
disposes its temporary editor after encoding the native Yjs seed.

```ts
import { createEditorCollaborationInitializer } from "@/lib/editor-collaboration"
import {
  createSchemaEditor,
  validateLexicalState,
} from "@/server/editor-schema"

export const initialize = createEditorCollaborationInitializer({
  createEditor: createSchemaEditor,
  validateState: validateLexicalState,
})
```

The `@/server/editor-schema` module is host code, not supplied source. Create
the canonical snapshot through authenticated document storage before
collaboration admission. A read-only ticket cannot promote a snapshot document.
Do not let browser content silently replace the canonical seed.

## Durable Objects with D1

Apply `editor-store/migrations/d1/0001-document-snapshots.sql` first. Apply
`editor-collaboration/collaboration/0003-do-canonical.sql` next. Do not apply
the PostgreSQL collaboration migrations to D1. Back up existing data before
migrations.

Create `createD1CollaborationCanonical(env.DB)` with the host D1 binding.
Construct `EditorCollaborationRoom(ctx, options)` inside the host worker class.
Supply `canonical`, `initialize`, `authenticate`, `policy`, `verifyCsrf`, and
`revalidate`. Also supply `origin`, `basePath`, `timeoutMs`, and `revalidateMs`.
The request timeout supports 1 through 30000 milliseconds. The revalidation
interval supports 1000 through 30000 milliseconds.

Use one stable SQLite-backed Durable Object identity per document. Forward
authenticated host requests without removing Origin or WebSocket protocol
headers. Delegate `fetch`, `webSocketMessage`, `webSocketClose`, and `alarm` to
the room. Map host WebSocket error handling to room close cleanup. No room
`webSocketError` method is supplied. Configure the host worker binding and
SQLite Durable Object migration explicitly. The copied room is not a complete
deployed worker entry point.

The room creates its local SQL tables and manages hibernatable WebSocket
attachments. D1 records canonical promotion and its coordinator. The room
retains authoritative collaboration state. Promotion across D1 and Durable
Object storage is not one transaction. Prepared state supports recovery; it does
not prove rollback after an uncertain result. Keep document-to-room routing
stable during recovery.

The D1 migration blocks direct changes to promoted canonical documents. Use an
explicit offline lifecycle migration for replacement or deletion. Do not remove
its guards to bypass an error.

## PostgreSQL with Bun or Node

Apply `editor-store/migrations/postgres/0001-document-snapshots.sql` first.
Apply `editor-collaboration/collaboration/0002-collaboration.sql` next. Apply
`editor-collaboration/collaboration/0003-collaboration-runtime.sql` last. Do not
apply `0003-do-canonical.sql` to PostgreSQL.

Supply a real `CollaborationTransactions` adapter. Its
`run(signal, deadline, work)` must execute `work(query)` on one database
transaction. Keep commit, rollback, cancellation, driver limits, and pool wait
limits in that adapter. Return binary columns as `Uint8Array`. Preserve integer
revisions without precision loss. Do not claim rollback when commit
acknowledgement is lost.

Create one shared log, ticket store, and session handler for PostgreSQL.

```ts
import {
  createPostgresCollaborationLog,
  createPostgresCollaborationTicketStore,
  createPostgresEditorCollaborationSessions,
} from "@/lib/editor-collaboration"
import { initialize } from "@/server/collaboration-initializer"
import {
  authentication,
  csrf,
  documentPolicy,
  logPolicy,
  revalidate,
  transactions,
} from "@/server/collaboration-host"

const log = createPostgresCollaborationLog({
  transactions,
  policy: logPolicy,
  timeoutMs: 5000,
  maxConcurrent: 8,
})
const tickets = createPostgresCollaborationTicketStore({
  transactions,
  timeoutMs: 5000,
})
const sessions = createPostgresEditorCollaborationSessions({
  transactions,
  log,
  tickets,
  timeoutMs: 5000,
  pollIntervalMs: 1000,
  revalidate,
})

const collaborationOptions = {
  origin: "https://editor.example",
  basePath: "/collaboration/",
  timeoutMs: 5000,
  authenticate: authentication,
  policy: documentPolicy,
  verifyCsrf: csrf,
  revalidate,
  transactions,
  log,
  tickets,
  sessions,
  initialize,
}
```

The host modules supply existing authentication, verified credential expiry,
CSRF checks, literal-true document policies, real SQL transactions, and the
schema-complete initializer. Do not treat these host requirements as bundled
services.

Create the native Bun service with
`createBunEditorCollaborationService(collaborationOptions)`. Pass its `fetch`
and `websocket` handlers unchanged to `Bun.serve`. Supply the hostname, port,
TLS settings, and connection limits from host configuration. Bun supports
host-supplied TLS.

```ts
import { createBunEditorCollaborationService } from "@/lib/editor-collaboration/collaboration-bun"

const service = createBunEditorCollaborationService(collaborationOptions)
```

Create the native Node service with
`createNodeEditorCollaborationService(collaborationOptions)`. The adapter uses
`node:http` and `ws`; it does not provide TLS. Bind the server to a private
interface behind a trusted HTTPS/WSS proxy. Preserve `Origin` and
`Sec-WebSocket-Protocol` through the proxy. Apply external connection,
handshake, header, body, idle, and rate limits.

```ts
import { createNodeEditorCollaborationService } from "@/lib/editor-collaboration/collaboration-node"

const service = createNodeEditorCollaborationService(collaborationOptions)
service.server.listen(3000, "127.0.0.1")
```

Call `service.close()` once during host shutdown after the listener starts.

The native adapters perform the authenticated upgrade and forward socket
lifecycle callbacks. They select only `editor-v1`, preserve message order, and
bound queued messages and bytes. Do not add a second unauthenticated upgrade
route. The protocol requires bounded text readiness, delivery, and ACK controls;
ordinary WebSocket send completion does not confirm durable delivery.

The sessions use durable PostgreSQL updates, tickets, leases, and presence rows.
They poll persisted changes across processes and recheck each recipient. Persist
accepted updates before broadcasting or reporting durable success. Do not
replace delivery acknowledgements with ordinary WebSocket send completion.

## Compose the browser

Create one controller and one stable extension array per mounted editor root.
Add `controller.extension` when creating `EditorRoot`. Compose
`EditorCollaborationRoot` inside that root with the same controller. Keep
`EditorContent` as the editable surface. Add `EditorCollaborationStatus`,
`EditorCollaborationAwareness`, and `EditorCollaborationCursors` where needed.

Pass explicit `documentId`, `permission`, `ticketUrl`, and `socketUrl` to
`createEditorCollaboration`. Use same-origin HTTPS ticket and WSS socket URLs.
Supply current host authentication and CSRF headers through `headers(signal)`.
Keep credentials out of browser storage and URLs. Destroy the controller when
the host removes the editor.

Use ordinary `EditorHistoryButton` controls for native per-client undo and redo.
Higher-priority host commands can veto history actions. Collaboration disables
local HistoryExtension only for the collaborative root. Unrelated editors retain
ordinary local history.

Host read-only settings remain authoritative. Permission, initial
reconciliation, and provider writable state must also permit editing.
Disconnected, syncing, denied, and conflicted clients cannot enable editing
through reconnect alone. Ticket `expiresAt` describes admission, not the
credential lifetime. The server enforces session credential expiry and closes
expired sessions.

## Bounds and recovery

Frames are limited to 65536 bytes. Encoded document state is limited to 61440
bytes. Awareness payloads are limited to 4096 bytes. Rooms support at most 32
clients. Additional structural, queue, delivery, and execution bounds can reject
smaller inputs. Synchronous Yjs work cannot be interrupted. Callback
cancellation requires host cooperation.

Durable update history is bounded by 256 updates and 1 MiB of update bytes. No
automatic compaction or online generation rotation is supplied. Plan an
authorized offline migration before history reaches its limit. Do not delete
history rows to force continued writes.

Offline edits and pending writes can have uncertain durable outcomes. Do not
automatically replay a local draft after reconnect. Use server coverage evidence
before claiming that a pending change committed. Otherwise, keep the draft
blocked and reconcile it explicitly outside the live session. Create a fresh
controller and root after host reconciliation.

Do not replace or import a complete document into an active collaboration root.
Document replacement, schema changes, and generation changes require an explicit
offline host workflow. No online import, automatic merge, cross-system rollback,
or lossless offline replay is promised.

## Verification required before deployment

Run real two-client workflows with each selected database and runtime adapter.
Check native history, cursors, host read-only, credential expiry, recipient
revocation, and uncertain delivery. Check recovery after process loss and failed
promotion acknowledgements. Check copied-source closure, worker isolation,
accessibility, and production output. These checks remain required; this guide
is not runtime evidence.

## Native Hocuspocus and WebRTC

Use native providers separately from the custom `editor-v1` service. Keep
credentials in memory. Store only the selected room ID.

```sh
bunx --bun @yopem-ui/cli add editor-collaboration-native
```

Import `createEditorNativeCollaboration` from
`@/components/editor/collaboration-native` in browser code. Connect it through
`createEditorCollaborationWithProvider` from the ordinary collaboration entry.
Supply an explicit HTTPS grant URL and a trusted WSS socket URL. Use the same
trusted origin for the grant and socket URLs. Supply explicit trusted WSS
signaling URLs before enabling WebRTC. No default signaling service is
configured.

The provider requires a grant for the exact room and generation. It stages the
authoritative Hocuspocus state before peer synchronization. The host must
initialize the canonical room once, with a complete Lexical schema. Browser
content must not become an implicit initial seed.

Native grants expire after at most five minutes. Their expiry must not exceed
the verified authentication expiry. Read-only grants must not contain peer
credentials. WebRTC requires trusted writers and uses at most nine connections.
The host must verify each credential, room, generation, permission, and expiry.

### Publish the grant endpoint

Install the portable server handler separately.

```sh
bunx --bun @yopem-ui/cli add editor-collaboration-grants
```

This item copies the handler and pure model, without browser or native SDK
imports. Keep both copied modules on the server.

```ts
import { createEditorNativeGrantsHttpHandler } from "@/lib/editor-collaboration/collaboration-native-grants"
import {
  authenticateEditor,
  documentPolicy,
  provisionNativeRoom,
  verifyEditorCsrf,
} from "@/server/editor-host"

export const nativeGrants = createEditorNativeGrantsHttpHandler({
  origin: "https://app.example.com",
  path: "/native-collaboration/grants",
  timeoutMs: 10000,
  maxConcurrent: 16,
  authenticate: authenticateEditor,
  policy: documentPolicy,
  verifyCsrf: verifyEditorCsrf,
  provision: provisionNativeRoom,
})
```

The `@/server/editor-host` module is host code, not supplied source. Forward the
original `Request` to `nativeGrants` from the configured POST route. Reuse the
handler instance so its capacity limit stays active. Supply existing OpenAuth or
Better Auth authentication with verified expiry. Approve CSRF and each document
action with literal `true`. Preserve opaque identity provider and user ID values
exactly.

`provision` receives the verified identity, requested permission, cancellation
signal, and effective deadline. It also receives the maximum permitted
credential expiry. Return the authoritative generation, seed confirmation, and
matching scoped credentials. Do not treat returned metadata as proof that the
external server enforces those scopes. The Hocuspocus host must enforce them
during authentication and document access. The peer host must control writer
membership, awareness identity, and shared credential rotation.

The handler reads the bounded request body once. Each host callback receives the
same body bytes and linked cancellation signal. The effective deadline shortens
when verified authentication expires. Callbacks that ignore cancellation retain
capacity until they settle. Dispatched host work can have an uncertain outcome
after cancellation.

### Native transport limits

Hocuspocus synchronization confirms a handshake, not durable storage. WebRTC
discovery does not prove that a peer is connected. Native providers do not use
`editor-v1` durable acknowledgements. They do not provide per-frame host
authorization or atomic revocation. The host must bound frames, decoder work,
awareness, storage, and connection resources. It must supply signaling, ICE
policy, durable storage, TLS, and server-side revocation.

Changing rooms must unmount the old roots before destroying their providers.
Keep host read-only state separate from current provider write permission.
Destroy providers and their owned documents during host cleanup. Check
reconnect, expiry, room changes, separate identities, and disposal with the real
selected services. These native workflows remain unverified under the current
execution pause.

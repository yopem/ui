## How theming works

Yopem components read semantic values from `src/styles/tokens.stylex.ts`. These
values include primary, background, foreground, font, and radius. Change that
file to update every component.

<span id="tokens" />

## Change the whole app

Complete [Installation](/docs/installation) first. Open the copied token file.
Replace the required values. Keep all other existing values.

```tsx
// Find these keys in src/styles/tokens.stylex.ts.
export const lightValues = {
  // Keep the other existing values.
  "--primary": "#1d4ed8",
  "--primary-foreground": "#ffffff",
  "--ring": "#2563eb",
  "--font-heading": '"App Sans", system-ui, sans-serif',
  "--radius-lg": "0.75rem",
}

export const darkValues = {
  ...lightValues,
  // Keep the other existing dark values.
  "--primary": "#93c5fd",
  "--primary-foreground": "#172554",
  "--ring": "#60a5fa",
}
```

Change background and foreground pairs together to keep text readable. Font
tokens select a font family. They do not download font files. Run a production
build after you edit tokens.

<span id="xstyle" />

## Component overrides

Use `xstyle` to change the appearance of one component. Yopem applies it after
default styles and variants.

```tsx
import * as stylex from "@stylexjs/stylex"
import { Button } from "@/components/ui/button"

const styles = stylex.create({
  pill: { borderRadius: "999px" },
})

export function SaveButton() {
  return <Button xstyle={styles.pill}>Save changes</Button>
}
```

Use `stylex.props` for native HTML elements. Use `xstyle` for Yopem components.
Keep focus, hover, and disabled styles when you override those states.

## Add dark mode

If your app has one fixed theme, do not add theme switching. A static light or
dark theme does not need a provider or client script.

To let users select light, dark, and system modes, copy these two files:

<ThemeFiles />

Add the script before hydration. Wrap your app with the provider. This example
keeps the TanStack Start head and script components. For another SSR framework,
change only those framework-specific imports.

```tsx
import "@/styles/styles.css"
import * as stylex from "@stylexjs/stylex"
import { createRootRoute, HeadContent, Scripts } from "@tanstack/react-router"
import { rootStyles } from "@/styles/tokens.stylex"
import { getRootThemeProps, ThemeScript } from "@/theme/theme"
import { ThemeProvider } from "@/theme/theme-provider"

export const Route = createRootRoute({ shellComponent: RootDocument })

function RootDocument({ children }: { children: React.ReactNode }) {
  return (
    <html
      {...getRootThemeProps("light")}
      data-theme="light"
      lang="en"
      suppressHydrationWarning
    >
      <head>
        <HeadContent />
        <ThemeScript />
      </head>
      <body {...stylex.props(rootStyles.body)}>
        <ThemeProvider>{children}</ThemeProvider>
        <Scripts />
      </body>
    </html>
  )
}
```

Add a control that calls `useTheme`. Use your existing Select or Segmented
Control component in the interface.

```tsx
"use client"

import { useTheme } from "@/theme/theme-provider"

export function ThemePicker() {
  const { theme, setTheme } = useTheme()

  return (
    <fieldset>
      <legend>Appearance</legend>
      {(["light", "dark", "system"] as const).map((value) => (
        <label key={value}>
          <input
            type="radio"
            name="theme"
            value={value}
            checked={theme === value}
            onChange={() => setTheme(value)}
          />
          {value}
        </label>
      ))}
    </fieldset>
  )
}
```

ThemeScript and ThemeProvider must use the same defaults. If your Content
Security Policy blocks inline scripts, pass its permitted per-request nonce to
ThemeScript.

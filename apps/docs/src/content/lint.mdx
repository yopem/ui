First, [choose a layout component](/docs/layout). Then,
[use StyleX to apply styles](/docs/styling).

## Rules

The local Oxlint plugin checks styling methods and component contracts. Enable
the optional StyleX rules if you need more checks.

- **yopem-ui/prefer-layout-primitives** (recommended): use design-system
  components instead of native layout and text elements. The rule checks
  wrappers, paragraphs, quotations, emphasis, marked text, and headings. Each
  diagnostic gives the replacement component. Use `Box render` or
  `Heading render` to keep the semantic tag. The rule does not check native
  anchors or framework links. Set `elements` to change the list of tags to
  check. Disable the rule for code that must use native elements.
- **yopem-ui/no-restyle** (recommended): limits StyleX properties in `xstyle` on
  imported UI components. By default, the rule permits only layout properties.
  The rule does not check Link by default. Use an existing `variant` prop for
  color and shape changes. Use an existing `size` prop for spacing changes. The
  rule checks local `stylex.create` declarations, arrays, and conditional
  styles. It does not check imported or computed styles that it cannot verify in
  the file.
- **yopem-ui/enforce-styling-methods**: permits `xstyle` and consumer
  `className` on imported UI components. The rule does not check Link by
  default. It rejects `css`, inline React styles, and direct `stylex.props`
  spreads on these components. Set `className: false` if your app uses only
  StyleX for styling. The docs app uses this setting.
- **yopem-ui/static-stylex**: requires StyleX declarations that static analysis
  can check.
- **yopem-ui/valid-polymorphic-as**: checks native tags on Box and heading
  levels on Heading.
- **yopem-ui/no-raw-stylex-colors** (off in the plugin's recommended preset):
  reports literal hex values and CSS color functions on color properties in
  `stylex.create`. The rule permits tokens. CLI init and the docs app enable
  this rule. The rule does not check shadows or other CSS strings.
- **yopem-ui/no-unused-stylex-styles** (off by default): reports unused
  top-level style keys in local `stylex.create` declarations. The rule tracks
  lexical scope, import aliases, dot access, string-literal bracket access, and
  dynamic style functions. It does not check exported objects or objects passed
  to other code. It does not check destructured objects or dynamic property
  access. It does not check declarations with spreads or computed keys. The rule
  cannot verify these uses in the file. Set `"yopem-ui/no-unused-stylex-styles"`
  to `"warn"` or `"error"` in your rules configuration to enable the rule. The
  rule has no automatic fix. Removal of styles can remove side effects.
- **yopem-ui/atoms** (off by default): controls the use of atoms. The default
  mode, `"allow"`, permits atoms and StyleX styles. The `"disallow"` mode
  rejects atoms imports. The `"enforce"` mode rejects `stylex.create`
  declarations. It also requires atoms in JSX `xstyle` and `sx` expressions. Use
  official atoms with StyleX styles, not inside `stylex.create` objects.

## Configuration

Run `bunx @yopem-ui/cli init` to install Oxlint and `@yopem-ui/oxlint-plugin`.
The command creates or updates `.oxlintrc.json` with the recommended rules and
raw-color checks. It does not change existing rules, including explicit `"off"`
values.

The configuration excludes copied `src/components/ui/` implementations from
Yopem rule checks. The rules check application JSX. Configure the plugin for
your application source. The following docs-app configuration permits `xstyle`
but rejects `className`. Copied components still provide `className` for
external integration.

**.oxlintrc.json**

```json
{
  "jsPlugins": [
    {
      "name": "yopem-ui",
      "specifier": "@yopem-ui/oxlint-plugin"
    }
  ],
  "overrides": [
    {
      "files": ["apps/docs/src/**/*.{tsx,jsx}"],
      "rules": {
        "yopem-ui/enforce-styling-methods": [
          "error",
          { "methods": { "className": false } }
        ],
        "yopem-ui/no-raw-stylex-colors": "error",
        "yopem-ui/static-stylex": "error",
        "yopem-ui/valid-polymorphic-as": "error"
      }
    }
  ]
}
```

Enable `no-restyle` to enforce component contracts. The plugin's
`recommendedRules` and CLI init include this rule. Docs previews currently
disable this rule but keep raw-color checks enabled.

```json
{
  "yopem-ui/no-restyle": [
    "error",
    {
      "allow": ["layout", "margin*"],
      "deny": ["marginBlockStart"],
      "exclude": ["^Legacy"],
      "contracts": [
        {
          "pattern": "^CardTitle$",
          "allow": ["fontSize", "color"],
          "deny": [],
          "message": "Use a {{component}} variant instead of {{property}}."
        }
      ]
    }
  ]
}
```

Use StyleX property names, `*` glob patterns, or categories in `allow` and
`deny`. The categories are `layout`, `spacing`, `color`, `typography`, `shape`,
`effects`, and `motion`. If you omit `allow`, the rule permits `layout`
properties. An empty `allow` array permits no properties. If a property matches
both `allow` and `deny`, the rule rejects it.

Contract regular expressions match imported component names. If more than one
contract matches, the rule uses the last matching contract. That contract
replaces only the keys that it sets. Use component name regular expressions in
`exclude`. Set `componentSources` and `styleComponents` to change the default
settings that identify imported UI components. Messages can contain
`{{component}}` and `{{property}}`. Use file overrides to exclude component
implementations from rule checks.

To use atoms, install `@stylexjs/atoms`. Compile atoms with the StyleX Babel
plugin. Use a default import for atoms. Combine atoms through StyleX props or
`sx`:

```tsx
import x from "@stylexjs/atoms"

const preview = <Button xstyle={[x.paddingInline._12px, x.color.blue]} />
```

Set `"yopem-ui/atoms": ["error", { "mode": "enforce" }]` to require atoms. This
mode rejects local `stylex.create` declarations. It also requires atoms in JSX
`xstyle` and `sx` expressions. The `"disallow"` mode rejects atoms imports. The
`"allow"` mode permits atoms and StyleX styles.

For a wrapper imported from `@apps/stylexjs/atoms`, set
`"source": "@apps/stylexjs/atoms"`. This repository does not currently include
that wrapper or the atoms dependency. Keep the atoms rule off until you install
and compile atoms.

Set `"yopem-ui/prefer-layout-primitives": "off"` in `.oxlintrc.json` to disable
the default native layout rule. To change the list of tags to check, use
`["error", { "elements": ["div", "span", "section"] }]`. Use Oxlint file
overrides for document shells or renderer code. An empty `elements` array
disables tag checks.

By default, the rule checks these tags:

- Layout tags: `div`, `span`, `main`, `section`, `article`, `aside`, `header`,
  `footer`, `nav`, `address`, `figure`, `figcaption`, `search`, and `hgroup`.
- List tags: `ul`, `ol`, `li`, `dl`, `dt`, and `dd`.
- Text tags: `pre`, `p`, `blockquote`, `em`, `mark`, and `h1` through `h6`.

Props, spreads, refs, conditional branches, and nested JSX do not exclude these
tags from checks.

Native elements inside a `render` prop are composition boundaries. The rule
permits these elements. It does not use CSS to identify the layout or rewrite
JSX. It does not check `render` values to require a specialized primitive.
Choose Flex, Stack, Grid, or another layout primitive for the required layout.

Use Prose for long-form content that is easy to read. Use Highlight for matching
words. Do not use either component as a replacement for all native tags. For
generic `pre` content, use `Box render={<pre />}`. Codeblock adds a toolbar and
a `div` wrapper. Thus, Codeblock is not a compatible replacement for a native
`pre` tag or its ref. Use Codeblock for code displays.

The rule permits native controls, tables, document metadata, SVG, custom
elements, unknown components, and framework links. Keep `strong`, inline `code`,
and other text tags that have no equivalent component as native elements. Use
file overrides to exclude copied primitive implementations and non-DOM renderers
from checks. Filenames and `data-slot` do not automatically exclude code from
checks.

The docs app enables this rule for all application JSX. It excludes only its
non-DOM Open Graph renderer. By default, `no-restyle` and
`enforce-styling-methods` do not identify registry Link as a UI component. Set
`styleComponents` explicitly to include registry Link in these checks.

Native framework elements, such as TanStack Router links, can use
`stylex.props(...)`. Use `xstyle` instead of a StyleX prop spread on imported UI
components. This lets the component combine its default styles and consumer
styles in order.

## Exceptions

The docs rules do not check registry implementations or non-DOM JSX renderers.
Run `bun run lint` from the repository root.
